# ⚡ Campus AI GrowthOS

**A campus-led referral engine and growth dashboard for the NxtWave Growth Intern Challenge.**

[**🌐 Live Demo**](https://nxtwave-campus-ai-growthos.onrender.com/) · [**📂 Source Code**](https://github.com/sumedh019/nxtwave-campus-ai-growthos)

> **Demo / simulation:** This project demonstrates a proposed student acquisition campaign. Sample registrations are synthetic, not actual workshop signups. This is an independent challenge prototype, not an official NxtWave registration portal.

## 🎯 The Challenge

Plan how to get **500 final-year engineering students** to register for the free online workshop **“Build Your First AI Project in 60 Minutes”** within **7 days** using a maximum **₹2,000** campaign budget.

The challenge is a simulation, so conducting real outreach or collecting actual registrations is not required.

## 💡 Growth Strategy

Focus on student-led distribution rather than relying primarily on paid advertising.

| Acquisition channel | Planning assumption | Target registrations |
| --- | --- | ---: |
| Campus ambassadors | 10 ambassadors × 25 signups | 250 |
| Peer-to-peer referrals | Additional referrals generated by students | 150 |
| Student clubs and communities | 5 groups × 15 signups | 75 |
| Paid promotion | ₹1,000 test budget at an assumed ₹40/signup | 25 |
| **Total** | **Targets, not observed performance** | **500** |

The model assumes **unique, eligible registrations** with no double-counting across sources. The proposed paid conversion cost and referral yield are hypotheses to validate, not verified benchmarks.

### Seven-day acquisition targets

| Day | New registrations | Cumulative | Main activity |
| --- | ---: | ---: | --- |
| 1 | 20 | 20 | Recruit ambassadors and prepare the campaign |
| 2 | 45 | 65 | Launch class-group outreach |
| 3 | 65 | 130 | Start referrals and club partnerships |
| 4 | 90 | 220 | Expand across engineering branches |
| 5 | 110 | 330 | Optimize top channels and test paid promotion |
| 6 | 100 | 430 | Ambassador and peer-referral push |
| 7 | 70 | **500** | Final campaign push and registration checks |

### Budget allocation

| Item | Budget |
| --- | ---: |
| Instagram promotion experiment | ₹1,000 |
| Ambassador recognition incentives | ₹600 |
| Creative materials | ₹200 |
| Contingency | ₹200 |
| **Total** | **₹2,000** |

**Target blended cost per registration:** ₹2,000 / 500 = **₹4** if the full target is achieved. This is a goal, not measured acquisition performance.

## 🧩 What the Prototype Does

- **Dashboard:** Displays the registration count, 500-student target, progress and acquisition-source breakdown.
- **Student registration:** Captures demo student details and checks duplicate email addresses within the same browser.
- **Referral links:** Creates a referral code and shareable link for a registered student.
- **Campus ambassadors:** Adds ambassadors, generates their referral codes and displays a leaderboard.
- **Growth insights:** Provides transparent, **rule-based** recommendations based on the locally stored demo dataset.
- **Budget tracker:** Records simulated spending against the ₹2,000 budget.
- **Demo controls:** Loads 130 synthetic registrations, resets local demo data and exports a CSV.

## 💻 Run Locally

This is a static website built with **HTML, CSS and vanilla JavaScript**. No framework, API key, dependency installation or build step is necessary.

```bash
git clone https://github.com/sumedh019/nxtwave-campus-ai-growthos.git
cd nxtwave-campus-ai-growthos
```

Open `index.html` in your browser. Alternatively, serve the folder locally:

```bash
python -m http.server 8000
```

Then open `http://localhost:8000`.

## 🧪 Three Proposed Growth Experiments

1. **Ambassador vs. direct outreach** — Hypothesis: trusted student introductions outperform generic posts. Compare tracked conversion rates and verified signups per source.
2. **Leaderboard vs. standard referral link** — Hypothesis: recognition increases referral participation. Compare active referrers and incremental verified registrations.
3. **Placement-focused vs. project-focused messaging** — Hypothesis: placement value improves relevance for final-year students. Compare click-through and registration conversion rates.

These are **proposed tests**, not experiments already run.

## ⚠️ Limitations and Responsible Use

This is a **front-end demo**, not a production-ready multi-user registration service.

- Data is saved to **browser `localStorage`**, so different browsers/devices **do not share a central database**.
- Email duplicate checks apply only to records stored in the current browser; they do **not** verify student identities or email ownership.
- The displayed signups are demo/simulated records and **not** NxtWave workshop registrations.
- Generated links can carry referral codes, but attribution and leaderboard results are **local to the browser**, not globally synchronized.
- Insights are deterministic rules; the application does **not** call a generative AI model.
- The application does not provide secure backend access controls, production-grade consent management or reliable anti-fraud verification.

**Before any real campaign**, add a secure shared database, server-side validation, verified opt-in, privacy protections, deduplication, attribution and event analytics.

## 🛠️ What I Would Improve Next

1. Add a shared backend and database so registrations are centrally available.
2. Add email verification, eligibility checks, consent records and fraud prevention.
3. Track visits, form completions and campaign source attribution to measure conversion.
4. Run small real-world messaging/referral tests, then adjust targets using observed results.
5. Add workshop reminders and attendance measurement with participant opt-in.

## 🧠 What I Learned

AI helped with campaign brainstorming, prototype development and deployment troubleshooting. I prioritized a referral engine instead of a landing-page-only asset, focused on organic distribution under a tight budget and moved from an unsuccessful file/Vercel workflow to GitHub + Render to ship a public demo. The important lesson was to use AI to accelerate execution **without confusing projections, simulations and measured outcomes**.
